# 報告書生成の性能・資源使用量

2026-11-24、Windows amd64、Go 1.27.4、24論理CPUの開発機で実測した。各条件1回の合成ログ測定であり、中央値・本番環境の保証値ではない。デスクトップ環境の他プロセスの影響を含む。CPU時間、OS全体のRSS、Java版の値はこの表では測定していない。

測定ツールは`tools/report-benchmark`。同一の全ログ生成方法、16個のIP、32パス、1秒ごとの時刻を用い、混在条件だけ5件ごとに`/.env`への404を含める。通常条件もルール上の統計・探索候補が成立し得るため、無検出を保証するデータではない。解析条件は既存既定値（maxKeys=4096、maxFindings=2000、evidence=32 MiB）。全成果物上限256 MiB。baselineは同じコードの従来`Analyze`経路で、bundleの追加処理を無効にしたもの。

| 条件 | 行数 | 入力bytes | 経過秒 | 行/秒 | 取得時点の最大HeapAlloc bytes | HeapSys bytes | spool bytes | 最終成果物bytes |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 従来解析・通常 | 100,000 | 9,412,500 | 10.515 | 9,510 | 20,463,712 | 28,999,680 | 対象外 | 対象外 |
| bundle・通常・spool16 MiB | 100,000 | 9,412,500 | 13.472 | 7,423 | 21,557,608 | 28,999,680 | 16,776,685 | 1,009,966 |
| bundle・20%混在・spool256 MiB | 100,000 | 9,258,750 | 30.231 | 3,308 | 227,796,800 | 398,065,664 | 95,767,078 | 80,122,511 |
| bundle・20%混在・spool16 MiB | 1,000,000 | 92,587,500 | 140.901 | 7,097 | 223,801,896 | 381,321,216 | 16,777,100 | 48,081,810 |

通常10万行のbundleは従来解析より約28%長い。追加I/O・hash・全統計・snapshot・別紙・HTMLがあるため、既存単一ファイルモードを選ぶ利用者にはこのコストを課さない。

全件spoolを保持した混在10万行と、spool16 MiBで打ち切った混在100万行では、サンプルピークヒープはそれぞれ約228 MBと224 MBだった。行数に比例して全観測をRAMへ保持する実装ではない。ただし設定された保持事案・証跡・集計キーと、JSONシリアライズ/マスク変換の一時コピーに比例するコストはある。設定値を増やせばピークメモリも増える。HeapSysはGoが確保したヒープ領域であり、HeapAllocやOS RSSと同じ値ではない。10ms間隔の観測は瞬間的なピークを取り逃がし得る。

spoolはレコード単位で上限内に収まり、100万行でも16,777,100bytes ≤ 16,777,216bytesだった。最終成果物＋spoolの保守的なディスク上界は混在10万行175,889,589bytes、混在100万行64,858,910bytes。これは両者の最大値が同時に存在すると仮定した上界で、実測ピークディスクではない。元入力はこの値に含めない。spoolは終了前に削除し、正常終了時の残存はテストで検証する。途中異常終了はINCOMPLETEで識別する。

全条件で入力は全行パースできたが、既定の集計キー/事案保持上限に達したため`complete=false`だった。混在条件では推奨対応保持上限も発生した。16 MiB条件はさらに全件spool上限に達し、証跡の完全性を下げた。256 MiB条件では全snapshotを書けたが、元の検出事案保持が不完全なため、`evidence_complete=false`を維持した。これらは意図した部分解析の実測であり、完全な全件攻撃分類を保証した測定ではない。

生値・警告は[performance-data.json](performance-data.json)。初めの2測定はwarnings項目の追加前のツールで取得し、後の2測定では警告全文も記録した。測定したfeatureコードはPhase 6の観点計数修正を含み、最後のCSV severity列・文書・サンプル追加前である。これらの差は性能保証の根拠にはしない。

再現例（各条件を同時実行しない）:

```sh
go run ./tools/report-benchmark --lines 100000 --mode analysis
go run ./tools/report-benchmark --lines 100000 --mode bundle
go run ./tools/report-benchmark --lines 100000 --mode bundle --mixed --spool-bytes 268435456
go run ./tools/report-benchmark --lines 1000000 --mode bundle --mixed
```

ツールはOSの安全なtemporary directoryを新規作成し、自分が作成した合成データと成果物だけを終了時に削除する。ツールの計測用readMemStatsとファイルstat自体にも負荷がある。
