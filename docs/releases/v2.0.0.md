WebAudit v2.0.0では、既存のバッチ解析に加えて、アクセスログのリアルタイム監視と外部コマンドHookを利用できるようになりました。設定ファイル、外部DB、常駐サービス、管理者権限は不要です。

## 主な変更

- `webaudit watch access.log` で追記を監視します。複数ファイル・ディレクトリ、renameローテーション、copytruncate、部分行、一時的なアクセス失敗に対応します。
- 既存のネイティブ検知・時間窓分析・相関・成否推定を再利用し、インシデントの作成・更新・終了を追跡します。`--format jsonl` は安定ID・revision・sequenceを持つイベントを出力します。
- チェックポイントをXDG/OS既定の状態ディレクトリに保存し、再起動後にオフセット・部分行・インシデント状態を復元します。`--no-state` と `--reset-state` も利用できます。
- `--on-detect` で指定した実行ファイルをシェルなしで起動し、検出イベントJSONを標準入力へ渡します。重要度・イベントのフィルタ、重複抑制、キュー上限、同時実行数、タイムアウト、子孫プロセスの終了管理に対応します。
- ローカルMMDBと既存キャッシュによる任意のGeoIP/ASN情報を監視イベントへ付加します。通常監視で外部API照会やDBダウンロードは行いません。
- 安全な通知サンプル、JSON Schema、性能測定ハーネス、ロードバランサー配下の配置・ログ収集・送信元IPに関するガイドを追加しました。

## 使い始める

```sh
webaudit watch access.log
webaudit watch access.log --from beginning --format jsonl
webaudit watch access.log --on-detect ./examples/notify.sh
```

初回は末尾から開始します。保存済み状態があれば `--from` より優先します。明示的に読み直すには `--reset-state --from beginning` を指定してください。Hookは指定時だけ同じOSユーザーで実行します。

## 互換性と制限

- 既存の `webaudit access.log` とHTML/JSON/CSVのバッチ解析を維持しています。バッチJSONは引き続き `webaudit/2`、watchイベントは独立したスキーマバージョン1です。
- HTTPステータス単独で侵害の成功を断定しません。国・ASNで攻撃判定や成否の確信度を変更しません。
- watchは有界保持です。保持上限、遅延廃棄、入力順などにより全履歴のバッチ解析と結果が異なる場合があります。Aura/Hubの別互換性レポート集合とカスタムlog-regexはwatchでは未対応です。
- polling/copytruncate競合による完全な欠損防止やHookのexactly-once配送は保証しません。Hookは信頼できる実行ファイルを指定し、重要な受信側はnotification_idを使って冪等に処理してください。
- 実測の連続監視は60秒、24時間分のイベント時刻は加速試験です。複数日の実時間耐久は未検証です。

詳細は[監視・Hookガイド](https://github.com/mikoto2000/webaudit/blob/v2.0.0/docs/watch.md)、[検証・性能記録](https://github.com/mikoto2000/webaudit/blob/v2.0.0/docs/watch-validation.md)、[ロードバランサー配下の利用](https://github.com/mikoto2000/webaudit/blob/v2.0.0/docs/load-balancer.md)を参照してください。

## 検証と配布

監視機能の統合時にWindowsの143トップレベルテストが成功（subtest含め333成功、既存の対象外Hub形式11件skip）。Windows/Linux CI、Linuxのレース検出・fuzz、通信syscallを禁止した実CLI watch/GeoIP/SIGINT試験が成功しています。

Windows / Linux / macOSのamd64・arm64向けバイナリ6種類と、`SHA256SUMS.txt`、`LICENSE`、`THIRD_PARTY_NOTICES.md`を添付します。SHA-256を照合して利用してください。Windows/Linuxは実行検証し、macOS / ARM64はクロスビルド対象です。
